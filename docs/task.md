### 實作補充（T2 實作時整理）
- API 契約在 `shared/storyApi.ts`：`POST /api/story`，key 只在 `Authorization: Bearer`，body 只有 `character`、`situation`；成功回 `{ story }`，失敗回 `{ error }`（`invalid_input` 另附 `fields`），錯誤類別只有本 app 定義的代碼，API 回應一律 `Cache-Control: no-store`。故事格式與驗證在 `shared/story.ts`，輸入驗證在 `shared/storyInput.ts`，Worker 與前端共用。
- OpenAI 錯誤對應：401 → `invalid_key`、403 → `permission_denied`、429 → `rate_limited`（錯誤代碼 `insufficient_quota` 時為 `insufficient_quota`）、其他 → `upstream_error`；連線失敗 → `network_error`、逾時 → `timeout`；拒絕 → `story_refused`；截斷、非 JSON 或不合格式 → `invalid_story`。只讀 OpenAI 錯誤的 `code`，不讀 `message`。
- 前端收到成功回應後再驗證一次故事格式，不合格同樣視為 `invalid_story`。
- key 欄位不用 `type="password"`，也不用 CSS 遮蔽（Safari 會把兩者當成密碼欄位並提議儲存 key）：輸入中顯示明文，離開欄位後顯示成圓點，按圓點或旁邊的眼睛按鈕可再顯示（做法使用者已確認；各瀏覽器是否仍提議儲存 key 見 T2.1 實作補充）。
- 本機 loopback 位址的 http 不導向、不拒絕（PLAN 3.2，使用者已確認），讓本機可以用非 https 測試。
- 移除 T1 的固定範例故事與「範例故事・固定資料」標示；還沒有故事時閱讀區顯示空白提示。新故事替換時閱讀區重建、回到第一頁；停止舊故事的朗讀與清除高亮留給 T3。
- 行為對應測試：`shared/story.test.ts`、`shared/storyInput.test.ts`、`server/index.test.ts`、`src/api/storyApi.test.ts`、`src/generation/useStoryGeneration.test.ts`、`src/httpsRedirect.test.ts`（全部使用假回應，不能證明真實模型的輸出品質、等待時間或帳戶權限）。
